# Selrano feature backlog

A running list of feature ideas for later. Not prioritized, not scoped — just a place to drop things so they're not lost. When one's ready to build, ask Claude for a copy-paste Claude Code prompt, and mark it Shipped here once it's run.

To add one yourself: drop a row in the table with today's date. Tell Claude to add an idea any time and it'll do the same.

| Status | Idea | Notes | Added | Source |
|---|---|---|---|---|
| Shipped | Study any deck anytime from Flashcards | Practice button on the Flashcards tab opens a flip-through session for the selected deck with no due-date gate. Study mode stays for SRS/due review and still calls `record_study_review`. Practice does not change the study schedule. | 2026-07-15 | Osman |
| Shipped | One-click "Add this deck to my workspace" on shared decks | Public `/d/<slug>` pages now clone into the signed-in user's workspace (signup/signin with `?next=` return + auto-add). Respects free deck limits; own decks redirect instead of duplicating. | 2026-07-15 | Grok / Osman |
| Idea | Magic link sign-in | Add alongside existing email + password. Supabase Auth supports this natively (`signInWithOtp`) — mostly UI + one new auth route, no schema change. | 2026-07-11 | Osman |
| Idea | Anki-compatible deck export (`.apkg`) | Students already have Anki habits; letting them export a Selrano-generated deck into Anki removes a reason to say no to trying Selrano first. | 2026-07-11 | Claude |
| Idea | Auto-generated quiz mode (multiple choice / short answer) | Same source material as flashcards, different review format — some students prefer testing over flip-cards. Could reuse the flashcard generation pipeline in `lib/ai-tools.ts`. | 2026-07-11 | Claude |
| Idea | Study streaks | Lightweight gamification on top of the existing `record_study_review` RPC — a visible streak count tends to noticeably improve return visits for spaced-repetition tools. | 2026-07-11 | Claude |
| Idea | Offline/PWA flashcard review | Studying often happens with bad wifi (libraries, transit). Even just caching due cards for offline review would remove real friction. | 2026-07-11 | Claude |
| Shipped | Chat says plainly when uploaded material doesn't cover a question | User feedback: "when the material doesn't support an answer, have the chat say that plainly instead of filling the gap." Built via Claude Code — system prompt now treats project context as source of truth and refuses to fill gaps with general knowledge, plus a fallback message for when no context matches at all. | 2026-07-14 | User feedback |
| Shipped | Inline citations linking to the exact page/passage in the source file | User feedback: "put a citation beside every factual answer that opens the exact page or passage from the uploaded file... users will judge grounded by how quickly they can verify one claim." Built via Claude Code. | 2026-07-14 | User feedback |
| Idea | Exam-date study plan | "Midterm on March 15 — schedule my reviews." Cap due cards per day and front-load weak material using existing `record_study_review` / SRS data. High perceived value for finals season; mostly product logic on top of current review state. | 2026-07-15 | Grok |
| Idea | Generate cards from a page/section range | Students upload whole syllabi/PDFs; they rarely want cards for every page. "Make a deck from pages 40–65 / this chapter heading" cuts noise and makes generation feel intentional. | 2026-07-15 | Grok |
| Idea | Weak-card / leech focus mode | Study session that only serves cards the user keeps missing (or overdue + low confidence). Turns existing review history into a "cram the hard stuff" mode without a new generation pipeline. | 2026-07-15 | Grok |
| Idea | Multi-file study pack → one deck | Select several lecture uploads and generate a single exam deck. Matches how courses actually work (many PDFs → one test) and reuses the flashcard pipeline. | 2026-07-15 | Grok |
| Idea | Chat with Selrano from Telegram | Link a Telegram account from Settings (one-time deep-link token, mirrors the existing referral-link flow), then message the bot like a friend — same memory, context, and chat history as the web app, same daily AI limit enforced. Pro-only. A full implementation plan already exists (migration, webhook, Settings UI, build order) — ask Claude for it when ready to build. Inspired by Photon's Spectrum multi-channel agent SDK. Shelved for now to focus on getting first users. | 2026-07-25 | Osman |
| Idea | Native mobile app | No requirements decided yet — platform (iOS/Android/both) and the actual driver (push notifications, offline access, app-store presence, native upload/camera flow) are all still open. Likely far cheaper to wrap the existing web app (React Native/Expo or Capacitor) than build fully native, unless a native-only capability turns out to be the real reason for it. | 2026-07-25 | Osman |
